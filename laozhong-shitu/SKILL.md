# laozhong-识图：原生多模态读图

识别本地图片或 URL 图片，输出文字描述或提取图中文字。适用于海报、截图、客户图片、直播画面、设计稿等。

> **核心**：当前模型 `deepseek-flash`（DeepSeek V4.1 Flash，2026-09-10 上线）**原生支持视觉输入**，直接用 Read 工具读图即可，不经过千问、不调用任何脚本。
>
> 2026-09-10 实测三条通道全部可用：① 裸 API 发 base64 → HTTP 200；② Read 工具读本地文件 → 直接出图；③ 对话里直接粘贴 → 直接出图。
>
> 千问链路已降级为**备用**，见第四节。

## 一、标准流程（本地图片）

**直接用 Read 工具读图片的绝对路径**，然后自己看图作答。

```
Read <图片绝对路径>
```

不需要脚本、不需要 API key、不需要千问。识别结果直接说给用户听，不用落盘成文件。

## 二、URL 图片

原生 Read **只能读本地文件**，http(s) URL 读不了。先下载再读：

```bash
curl -sL "<图片URL>" -o "~/_img_temp.png"
```

然后 `Read ~/_img_temp.png`。

`_img_temp.png` 是临时产物，用完清掉。扩展名按实际格式改（png / jpg / webp）。

## 三、对话里粘贴的图片

用户直接粘贴进对话的图，系统会在图片下方标注来源路径，例如：

```
[Image: source: ~/xxx.png]
```

**这个路径是真实可用的**——粘贴的图同样能反过来用脚本处理（提取、转存、二次识别）。

## 四、备用链路（可选）

原生多模态已经够用，一般不需要备用。只有两种情况才考虑：

- 需要把识别结果**落盘成文件**
- 原生链路异常，需要交叉验证

如果你另配了视觉 API（例如阿里云百炼 DashScope 的 `qwen3-vl-plus`，Anthropic 兼容端点 `https://dashscope.aliyuncs.com/apps/anthropic/v1/messages`），自己写一个小脚本调用它、结果用 UTF-8 写进文件，再用 Read 读回来。

> ⚠️ Windows 下别用 PowerShell `>` 重定向保存结果——它写 UTF-16，Read 会报 binary。让脚本自己按 UTF-8 写文件。

## 五、安全

- API key 放环境变量，不写进文档、记忆、日志；识别任务不打印 key
- 识别出的证件、身份证号、证书编号等敏感内容，**不要落盘到临时文件**

## 六、适用范围

- 需要「看懂图片」的任务：海报/设计稿检查、截图文字提取、客户发来的图片、直播画面、配图审核等
- 支持格式：png / jpg / jpeg / gif / webp / bmp
- 不适用：视频、音频（只处理静态图片）
