# 协作出稿流程

> 分类：08-场景编排 | 编号：待补 | 创建：2026-09-28 | 来源：2026-09-28《高敏感和淡人伴侣的相爱相杀》全程实战

---

## 触发场景

- 用户发来一个**写到一半的脚本**，说「没写完，你协助我一起」「辅助我把它补完」。
- 用户说「我组织不清楚」「我不知道我知道什么」「我知道一些东西但说不出来」。
- 用户要求「你以反问我的形式，让我把这些内容补充完」。
- 触发词：「/协作出稿」「协助我把这个脚本完成」「你反问我」。

## 与相邻 skill 的分界

| skill | 干什么 | 不干什么 |
|-------|--------|---------|
| `laozhong-jiaobenpaiban`（/脚本排版） | 清理、排版、查措辞、查矛盾 | **不改内容、不补内容** |
| `laozhong-jiegou` | 只调叙事顺序，不写新内容 | 不取料、不补段 |
| **本 skill** | **用户口述料 → 组织成段 → 缺口补齐 → 定稿** | 不排版、不重排顺序 |

> **判据：用户手上有一篇半成品 + 说不清的组织 → 本 skill。用户手上是成品只要整理 → 脚本排版。**

## 核心铁律（全程不可违反）

1. **不润色——用户补充的信息、用户写的段落，不改结构、不加观点、不加句子。只改措辞、只删多余的口语词。**（2026-09-28 用户明确要求「下次沿用流程里必须注明」）
   - 判断标准：**动完之后，读者能看出哪句是用户的、哪句是万万的吗？**如果加了过渡句、加了总结句、加了替用户写的结尾句，就已经越界。
   - 需要动内容（删段、换例子、调顺序）→ **先问，等点头再动**。
2. **不跳步的两级确认**：① 先对方向（落点／听众／记住哪句／有无真实料）→ ② 再对具体文案。两步都过才动笔。
3. **出结构表、标字数、让缺口可见**——缺口是算出来的，不是感觉出来的。
4. **反问取料，问具体场景不问抽象观点**——问「他当时第一反应是什么」，不问「你怎么看淡人」。
5. **有分歧列方案，用户定了就照办，不反复劝。**用户否决方案后不再回劝，直接按他的定。
6. **不虚拟真实料**。淡人的内心、案例、来访者细节一律由用户提供。用户没有真实案例就走普遍化描述，**绝不编造具体人名故事**。
7. **字数一律用 Python 数，口径＝含标点、不含空格**（沿用 `laozhong-jiaobenpaiban`（/脚本排版）铁律 4）。**报数时带口径**（如「1838 字，含标点不含空格」）。**禁用估算下结论。**

## 四步流程

### ① 先定方向，一个字都不写

确认四件事，缺一件不动笔：

1. **「给出路」落在哪？**认知翻转 / 方法论 / 判断标准 / 镜像代入……（本 skill 的常见答案是认知镜像型）
2. **目标听众是谁？**（正在经历的人 / 已结束复盘的人 / 两批都要）
3. **如果只让观众记住一句，是哪句？**这句是主线，还是只是一个亮点？
4. **有没有可用的真实案例？**要一句脱敏概括（谁＋什么情境＋转折点）。没有就明说走普遍化。

同时问清**字数区间**（用户一般会给，如 1800–2300）。

### ② 出结构表，标字数，让缺口可见

把全篇拆成 5–6 段，每段标上目标字数，并与现有素材的实际字数对齐。

| 段落 | 内容 | 字数 |
|---|---|---|
| ① 钩子 | 开场那个二选一 | 150 |
| ② 主线 | 要让人记住的那句判断 | 400 |
| ③ 机制 | 双方机制差异 | 450 |
| ④ 切镜头 | **对方向独白**（最容易缺料的一段） | 400 |
| ⑤ 递进 | 反常识的第二层 | 260 |
| ⑥ 落点 | 最小动作 + 认知落点 | 430 |

**报缺口要报数**：现有素材多少字、缺口多少字、缺口在哪几段。

### ③ 反问取料（一次 3–5 问）

- **一次只问 3–5 个**，不做长清单轰炸。
- **问场景，不问观点**。差的问法：「你怎么理解淡人伴侣的内心？」好的问法：「你说了一句很重的话，他当下第一反应是什么？他为什么不说出来？」
- **问到「具体动作」为止**。用户说「累」，要追到「累在哪一个动作上」。
- **允许用户一次给一大堆**——用户口语回答时经常一口气给六七点，**不要打断，全收下**。
- 收完料先**把散料归位**（见 ④），再动笔。

### ④ 散料归位，别集中塞一处

用户一次给的六七点，拆成几块分放不同段。**不集中塞进一段**，否则那一段过长、节奏拖。

> 实例（2026-09-28）：用户一次给 6 点 → 第 1 点进独白开场、第 2 点进独白主体、第 3 点进独白收尾、第 4 点进高敏感侧、第 5 点进 ⑤、第 6 点备选。六点分放三处，独白没有变成一坨。

### ⑤ 定稿核字数

- 逐段核字数，报总数（含口径）。
- 最终稿落盘到**项目作业区**（用户做新脚本的目录，如 `桌面\脚本整理\`），不是归档目录。
- 落盘后**回读确认文件真实存在**（参照 `laozhong-jiaobenpaiban`（/脚本排版）踩坑：贴路径≠文件已写）。

## 判断与措辞的边界（哪些必须提，哪些不许碰）

### 必须提（提了还要给改法）

| 类型 | 实例（2026-09-28） |
|------|-------------------|
| **引用不明** | 「而这两样东西」——指代不清，直接删 |
| **编导视角** | 「上一段说他『再努力一次』」——不是讲给观众听的话，删 |
| **逻辑反了** | 「他又何尝理解不了你的高敏感呢」是双重否定，字面和原意相反 |
| **重复** | 同一层意思前后说两遍（③ 的「你补得越完整」与 ⑥ 重复） |
| **跑题** | 落点里突然转去讲「遇到居心不良的伴侣后果不堪设想」——把「看见彼此」拖成「提防坏人」 |
| **替观众总结** | 观众本来听得懂的话后面再加一层解释 → 多此一举 |

### 不许碰

- 用户的原句、原观点、原结构。
- 用户自己定的收尾方式、自己选的词（如「吹哨人」这类他的口头语，原样保留）。
- 用户说「不调」的地方——**照原样出稿，不再回劝。**

## 实战案例：《高敏感和淡人伴侣的相爱相杀》（2026-09-28）

**起点**：用户发来半成品约 1100 字（现象→反常识→机制差异→失控感→脑补链条），说「没写完，你协助我」。

**方向四件**：给出路＝让她看见信息差（不是给方法）／听众＝正在被冷落想修复的高敏感方＋已分手的／主线＝「能把他逼到想跑，恰恰说明他陷得深」／案例＝有（忽冷忽热两三个月→突然热情→仍在找不对劲→他爆发）。

**结构表**：六段，缺口在 ④ 独白和 ⑥ 落点。

**取料 6 问**，用户一次给 6 点（懵逼、说多了没用、装不知道、被纠错像被父母纠错、他还会再努力一次、案例），全收下后分放三处。

**用户补的三块原稿**（本 skill 的核心资产，只做措辞收拾）：
1. **淡人第一人称独白**——「你问我是不是不爱你，我第一反应是懵」「不说最好，不说你就不会有情绪」「配合就是态度」「有时候我确实是装的」「像小时候被父母纠错」
2. **他的第二次努力**——「他一边主动，一边在心里算」「我已经努力过了，你也看见了，可你还是不信我」
3. **落点**——「吹哨人」那条线（从小被父母这么对待 → 自己也同化成了吹哨人 → 表面找对方的问题，实际在惩罚自己 → 做不到课题分离）＋「先从看见事实开始」（他一边吐槽一边帮忙 = 帮忙是事实；你说他冷漠 = 他回复了是事实）

**定稿 1838 字**（含标点不含空格），落盘 `桌面\脚本整理\高敏感和淡人伴侣的相爱相杀.md`。

**用户当场拍板的四处删除**：
- ② 结尾「而这两样东西，从一开始就没人教过你们怎么处理」→ 引用不明，删
- ⑤ 结尾「上一段说他『再努力一次』……」→ 编导视角，且替观众总结，整段砍
- 落点里「遇到居心不良的伴侣，后果不堪设想」→ 跑题，砍
- 原本的极简落点（一句动作＋一句金句）→ 用户评「落点太简陋」，换成用户自己写的「看见事实」版

## 踩坑记录

- **别报估算的字数**（2026-09-28）：估算 1950 字，实际 1743 字，偏 200 字。**逐段核完再报，报数带口径。**
- **不要擅自替用户写原文**（2026-09-28）：在用户补的落点里加了过渡句「那要走出来，从哪一步开始？」和总结句「事实是他做了，感受是你没被满足」（后一句用户后来自己要了），属于越界；用户提醒后全部撤回。**这就是「不润色」铁律的由来。**
- **不要把落点写成劝说**（2026-09-28）：初版落点用「你错得有多离谱」在教育观众，用户指出「落点太简陋」。**落点要给能对照的事实，不给训话。**
- **解释要短**（2026-09-28）：用户问某句「作用是什么」，回了两个作用＋两个问题，用户实际只需要一句「它是编导视角，多余」。**能一句话说清就不写三段。**
- **用户一次给很多料是常态**，不是要你全塞进同一段——先归位再写。
- **用户明确说「不要」的段落，不要再解释它的价值**——直接删，然后给出删完的定稿。
